# 大模型大规模分布式训练并行策略

## 物理约束与层次化互联拓扑

### 扩展瓶颈与层次存储

* **分布式并行扩展（Distributed Parallel Scaling）**

    * > **定义**：将单个深度神经网络模型的计算图、状态张量或训练数据切分分摊至多个物理互联的加速芯片，协同突破单芯片物理限制的系统工程技术。

    * 物理动因与双重约束：大模型扩展受制于显存容量墙与算力吞吐墙。参数量达到数百亿至万亿规模时，仅模型权重与优化器状态即需数百 GB 至数 TB 显存，单卡物理显存无法启动装载；即便较小模型可塞入单卡显存，单芯片浮点算力上限亦导致遍历预训练语料所需时间超出工程承受底线，必须借助多设备协同缩短训练周期。

    * 核心权衡法则：利用多设备算力换取训练耗时压缩的同时，必须额外支付跨设备互联通信的带宽与延迟代价。分布式系统设计的根本任务是在物理互联带宽受限的前提下编排计算流与通信流，避免昂贵的算力引擎因等待数据搬运而空转。

* **层次化存储与互联拓扑（Hierarchical Memory and Interconnect Topology）**

    * > **定义**：从单芯片片上微架构缓存延伸至数据中心跨节点网络所构成的多级带宽与延迟梯级架构。

    * 四级层级拓扑与带宽梯阶：
        * 片上存储层：流式多处理器私有的一级缓存（L1 Cache）与片上共享内存（Shared Memory），延迟极低，物理带宽达数十 TB/s。
        * 单卡全局显存层：片外高带宽显存（High Bandwidth Memory, HBM），带宽为数 TB/s（例如 Blackwell B200 约为 8 TB/s）；在单卡微架构视角下属于访问瓶颈，在分布式多卡视角下则被视为高速局部数据底座。
        * 单节点多卡互联层：通过专用高速总线与硬件交换芯片实现节点内多卡互联，带宽达数 TB/s（例如第五代 NVLink 单卡双向聚合带宽达 1.8 TB/s，约为本地 HBM 带宽的四分之一）。
        * 跨节点集群网络层：通过网络适配器与交换网络线缆互联，带宽为数十至数百 GB/s（例如 InfiniBand 或融合以太网 RDMA），延迟显著增加。

    * 单卡与多卡优化手段对偶：单卡微架构通过算子融合（Operator Fusion）与分块循环（Tiling）消除片上与 HBM 之间的冗余访存；分布式多卡架构通过张量分片（Sharding）与副本复制（Replication）消除跨设备互联总线上的冗余通信。

### 现代网络互联与底层通信运行时

* **节点内专用交换拓扑（Intra-Node Switch-based Topology）**

    * > **定义**：单机内部所有计算设备均通过高带宽专用物理链路直接接入集中式硬件交换矩阵所构成的完全互联拓扑。

    * 演进机理与带宽指标：PCIe 仍广泛用于 GPU 与主机、网卡及 GPU 之间的连接；NVLink/NVSwitch 可提供更高带宽的 GPU 互联。1.8 TB/s 是 B200 的第五代 NVLink 单 GPU 双向聚合规格，不是所有 8 卡服务器的统一带宽。

    * 机架级扩展形态（GB200 NVL72）：18 个计算托盘，每个含 2 颗 Grace CPU 与 4 张 Blackwell GPU；另有 9 个 NVLink 交换托盘，共 36 CPU、72 GPU。

    * **原课件勘误**：[lecture_07.py，第 229 行](https://github.com/stanford-cs336/lectures/blob/de53a9f979a6ee35f7d13a5e1aadee5ea1afc58e/lecture_07.py#L229) 的“9 个计算托盘、每个 8 GPU”应为“18 个计算托盘、每个 4 GPU”；另有 9 个交换托盘。

    * 非对称拓扑短板规则：整个集群在集合通信中的步调取决于通信最慢的节点。若在 8 卡 NVLink 高速服务器外部混接一块通过普通网络互联的独立 GPU，跨节点链路的狭窄带宽与高延迟将成为木桶短板，导致所有卡在每一步集合通信中均被迫阻塞等待，使高速 GPU 算力严重耗损。

* **远程直接内存访问（Remote Direct Memory Access，RDMA）**

    * > **定义**：RDMA 允许设备直接访问已注册的远端内存，降低数据传输路径的 CPU 和内核参与。访问 GPU 显存还需要 GPUDirect RDMA 等支持；普通 RDMA 的目标也可以是主机内存。

    * 传统协议栈中转链路：发送端 GPU 将 HBM 数据经由 PCIe 拷贝至主机内存（Host RAM），操作系统 CPU 介入分配内核套接字缓冲（Kernel Socket Buffer）并执行协议栈封包，随后推入网卡发出；接收端逆序重复多次内存拷贝与 CPU 中断，引入毫秒级端到端延迟并挤占 CPU 周期。

    * RDMA 数据路径可绕过主机协议栈；GPUDirect RDMA 在兼容的网卡、GPU、驱动与 PCIe 拓扑下可避免经主机内存中转。连接建立、内存注册和控制操作仍可能由 CPU 执行。

    * 底层物理载体分类：
        * NVLink + NVSwitch：硬件协议层原生支持跨设备内存直接读写。
        * InfiniBand（IB）：高性能计算专用网络硬件，原生提供高吞吐与超低延迟 RDMA 支撑。
        * 融合以太网 RDMA（RDMA over Converged Ethernet，RoCE）：在主流无损以太网基础设施之上封装 RDMA 语义，通过无损网络机制绕过 CPU 协议栈，以较低成本逼近 InfiniBand 性能。

* **集合通信库运行时（NVIDIA Collective Communications Library，NCCL）**

    * > **定义**：面向多 GPU 分布式通信的高性能运行时库，充当深度学习框架与物理底层互联网络之间的软件抽象与调度层。

    * 核心运行时机制：
        * 拓扑自动发现：在初始化阶段探测底层硬件的物理互联状态（识别 NVLink、PCIe 树、InfiniBand 网卡对应关系）。
        * 逻辑拓扑构建：依据物理连通度规划最优通信路径，动态构建高效的环路（Ring）或树形（Tree）拓扑。
        * 通信算子派发：在 GPU 上直接派发专用的通信计算内核（Communication Kernels），调度 GPU 算力单元与 DMA 引擎驱动数据在设备间直接收发。

### 硬件架构分歧与系统工程权衡

* **环形网格与胖树拓扑（3D Torus and Fat-Tree Topologies）**

    * > **定义**：大规模加速器集群底层网络互联的两种典型体系结构，分别代表固定邻居连接网格与多级交换全互联树形设计。

    * 拓扑机理与适用特征对比：
        * 3D 环形网格（3D Torus，以 TPU 为代表）：每个芯片仅与三维空间物理相邻的邻居相连且首尾闭环。集群扩展时单节点网络端口数与连接度保持恒定，成本可控且能效优异，适合模式规整且高度对称的稠密张量切分与数据并行。
        * 胖树拓扑（Fat-Tree，以 GPU 集群为代表）：节点内通过 NVSwitch 全互联，跨节点通过 ToR、汇聚与核心多层交换机级联，旨在提供全局任意两点间的高吞吐无阻塞通信，适合处理动态路由与随机离散通信流量。

    * 拓扑随 TPU 型号变化：v5e 使用 2D torus，v5p 使用 3D torus。课堂此处讨论的新一代 TPU 与 Virgo 网络不能改写成 v5e/v5p 的统一规格；MoE 的 All-to-All 流量会影响互联设计。

* **高互联功耗与单芯片算力权衡（Interconnect-Power Trade-off）**

    * > **机理**：单芯片算力处于劣势时，系统架构可通过激进堆叠光纤交换互联构建超大规模高速域以弥补吞吐不足，其工程代价为整机功耗与散热开销成倍攀升。

    * 典型工程样本：课程以 CloudMatrix 384 超节点讨论“大互联域换取系统吞吐”的权衡。384 是超节点芯片数，不能写成普通单机架规格；功耗比较必须同时说明硬件、精度、吞吐和整套系统口径，不能把课堂估算推广为固定的 4 倍法则。

## 集合通信原语与有效带宽建模

### 进程管理与基础点对点聚合

* **分布式通信抽象与环境初始化（Distributed Environment Setup）**

    * > **定义**：将多设备协同通信模式封装为标准化抽象模板、并建立跨进程协作通道的编排模型。

    * 编排术语规范：
        * 进程秩（Rank）：进程组内的进程编号。GPU 训练常采用一进程一 GPU，但这不是 Rank 的定义或强制约束。
        * 世界大小（World Size）：当前进程组中的进程总数，记为 $`W`$。

    * 初始化配置规则：通过 `dist.init_process_group` 初始化进程组。环境变量 `MASTER_ADDR` 与 `MASTER_PORT` 仅用于初始化阶段的元数据交换与握手协调，后续海量张量物理传输完全由 NCCL（GPU 平台）或 Gloo（CPU/无 GPU 平台）底层通道承载。

* **广播与切片收集原语（Broadcast, Scatter and Gather）**

    * > **定义**：在指定根节点（Root Rank）与全体设备之间进行单向复制或维度切分拼装的基础集合通信算子。

    * 算子机理与应用场景：
        * 广播（Broadcast）：Root 节点将其本地张量完整复制分发至所有设备，操作完成后各 Rank 持有相同副本。主要用于初始权重加载与检查点（Checkpoint）分发。
        * 分散（Scatter）：Root 节点将全局大张量沿特定维度等分为 $`W`$ 份，分别投递给对应的 Rank 独立持有。
        * 收集（Gather）：Scatter 的严格逆操作，Root 节点从所有 Rank 收集局部张量切片，按 Rank 编号顺序沿指定维度拼接成全局张量。

* **规约原语（Reduce）**

    * > **定义**：在收集各 Rank 对应位置张量数据的同时、执行满足结合律与交换律的二元代数操作并将最终结果存入指定根节点的集合操作。

    * 运算规则与广义抽象：支持求和（Sum）、最大值（Max）、最小值（Min）与乘积（Prod）。从高层抽象审视，Gather 本质上属于一种代数算子为“张量维度拼接”的广义规约。

### 核心分布式训练集合通信算子

* **全收集（All-Gather）**

    * > **定义**：每个设备贡献自身持有的局部张量切片，操作完成后所有设备均获得沿指定维度拼接而成的全局完整张量的集合操作。

    * 训练应用场景：FSDP 在计算层前收集完整参数；列 TP 的输出可以保持特征分片，交给后续行 TP，无需立即 All-Gather；Megatron 式 SP 的 LayerNorm 按 token 本地执行，在后续列并行 GEMM 前才 All-Gather 序列。

* **规约分散（Reduce-Scatter）**

    * > **定义**：对所有设备对应位置的张量执行全局元素级规约（通常为求和），随后将规约后的张量均匀切分为 $`W`$ 份分别写入对应 Rank 本地显存的集合操作。

    * 训练应用场景：在反向传播过程中，各卡计算出对应于本地数据切片的梯度，调用 Reduce-Scatter 既完成全局梯度求和累加，又直接将求和后的梯度分片存储至对应的负责 GPU 上，天然配合分片优化器状态更新。

* **全规约（All-Reduce）**

    * > **定义**：对所有设备上的张量按位相加（或其他结合律运算），并将完全相同的累加规约结果同步分发至全体设备的集合操作。

    * 算子语义等价关系：在相同规约与切片约定下，All-Reduce 的结果可由 Reduce-Scatter 再 All-Gather 构造；实际实现也可能使用树、分层算法等，因此网络流量与耗时不必相同。

        $`\displaystyle \text{All-Reduce}(X) \equiv \text{All-Gather}(\text{Reduce-Scatter}(X))`$

    * 工程应用分歧：基础数据并行（DDP）直接调用一步到位的 All-Reduce；高级显存分片技术（ZeRO/FSDP）则将 All-Reduce 拆解为独立的 Reduce-Scatter 与 All-Gather，在两个通信间隙插入局部优化器参数更新与权重显存即时释放。

* **全到全通信与动态路由（All-to-All Collective）**

    * > **定义**：每个 Rank 将本地持有的张量划分为 $`W`$ 份并分别定向投递给 Rank $`j`$、同时接收来自所有其他设备的对应分块的集合通信原语。

    * 矩阵转置等价性：若各设备之间传输的分块数据量完全对称相等，All-to-All 操作在二维分块矩阵视角下严格等价于一次分布式矩阵转置（Matrix Transpose）。

    * 混合专家模型基石：在混合专家模型（MoE）中，每个设备持有一部分 Token 激活值并维护特定专家网络。门控路由器为各 Token 选定目标专家后，系统通过 All-to-All 原语将 Token 跨卡分发至对应专家节点；专家计算完毕后，再次通过逆向 All-to-All 将输出激活送回原始卡。

### 异步执行流与双重同步机制

* **双重异步执行流（Dual Asynchronous Execution）**

    * > **定义**：单设备内部 CPU 发射与 GPU 执行的异步队列机制，以及集群多设备进程之间时钟无锁步的时序交错特性。

    * 异步机理：PyTorch 调用 CUDA 算子时默认采用非阻塞的异步发射（Asynchronous Launch），Python 代码返回时底层 GPU 队列中的核函数往往仍在排队或运行；在多卡分布式环境下，各进程独立的 CPU 执行进度与各卡的 GPU 计算流水相互交错，构成双重异步。

* **两级同步屏障规则（Two-Level Synchronization Barrier）**

    * > **定义**：为实现严格全局状态对齐而配合使用的单卡本地流同步与跨进程分布式屏障。

    * 编码调用规范：
        ```python
        # 第一级：单卡本地流同步，强制当前进程阻塞等待本地 GPU 队列执行完毕
        torch.cuda.synchronize()

        # 第二级：跨进程分布式屏障，阻塞等待集群所有 Rank 全部抵达该行代码
        dist.barrier()
        ```

    * > **同步边界**：NCCL 的 `dist.barrier()` 会用 GPU 集合通信实现屏障，并阻塞 CPU 等待该操作完成。它不是所有 CUDA 流的通用设备栅栏；基准计时可在边界显式同步设备。没有“任何 barrier 前必须先 cuda.synchronize，否则死锁”的规则，死锁应检查集合通信顺序、参与进程、设备选择和流依赖。

* **异步非阻塞通信句柄（Non-blocking Communication Handles）**

    * > **机理**：`async_op=True` 返回 Work 句柄，允许安排独立计算。CUDA 上 `work.wait()` 通常建立当前 CUDA 流对通信结果的依赖，不等于主机等待所有 GPU 工作完成；读取结果、跨流使用和计时应按后端文档显式同步。

### 环形通信算法与有效带宽推导

* **环形通信双阶段推导（Ring-based Collective Mechanics）**

    * > **定义**：NCCL 等通信运行时将 $`W`$ 个物理 Rank 逻辑组织成单向闭合通信环路（$`0 \to 1 \to \dots \to W-1 \to 0`$）以优化总线利用率的算法实现。

    * 算法阶段拆解（设待同步张量总字节数为 $`S`$，均分为 $`W`$ 块，每块体积为 $`S/W`$）：
        * 阶段一（Ring Reduce-Scatter）：环路循环迭代 $`W - 1`$ 步；每一步中各 Rank 将手中某块发往下游，同时从上游接收对应块并执行本地元素累加。经历 $`W - 1`$ 步接力，各分块的全局规约求和完成并分散在各卡。单卡累计发送字节数为：

            $`\displaystyle \text{Data}_{\text{RS}} = (W - 1) \times \frac{S}{W}`$

        * 阶段二（Ring All-Gather）：环路再次循环迭代 $`W - 1`$ 步；每一步中各 Rank 将已规约好的分块向下游转发覆盖。经历 $`W - 1`$ 步流水线接力，所有设备收齐全部 $`W`$ 个分块并恢复全局张量。单卡累计发送字节数为：

            $`\displaystyle \text{Data}_{\text{AG}} = (W - 1) \times \frac{S}{W}`$

    * 全流程通信量汇总：

        $`\displaystyle \text{Data}_{\text{All-Reduce}} = \text{Data}_{\text{RS}} + \text{Data}_{\text{AG}} = 2 \times \frac{W - 1}{W} \times S`$

        集群全网总传输字节数为 $`2(W - 1) \times S`$。

* **有效通信带宽模型与线性扩展性（Effective Bandwidth and Linear Scalability）**

    * > **定义**：基于端到端实际物理耗时 $`t_{\text{wall}}`$ 与算法有效数据移动量计算得出的标准化通信吞吐标尺。

    * 数学公式与渐进定理：

        $`\displaystyle \text{Bandwidth}_{\text{eff}} = \frac{\text{Data}_{\text{All-Reduce}}}{t_{\text{wall}}} = \frac{2 \times \left(\frac{W - 1}{W}\right) \times S}{t_{\text{wall}}}`$

        随着参与训练的物理 GPU 数量 $`W`$ 持续增长：

        $`\displaystyle \lim_{W \to \infty} \frac{W - 1}{W} = 1 \implies \text{Data}_{\text{All-Reduce}} \approx 2S`$

    * 扩展性边界：Ring 的单卡发送量趋近 $`2S`$，但步数是 $`2(W-1)`$，延迟项、竞争与网络拓扑仍会随规模增长；固定字节量不能证明线性扩展。

    * Reduce-Scatter 性能特征：同样的 Ring 分片下发送量是 All-Reduce 的一半；只有在带宽主导、链路和实现可比时，耗时才可能接近一半。

## 数据并行架构与零冗余显存优化

### 经典数据并行与梯度同步机制

* **样本切分与副本复制（Data Partitioning and Model Replication）**

    * > **定义**：各计算节点全量保留模型架构与参数副本、仅沿样本批次维度切分训练数据的分布式并行范式。

    * 运行机理与局部批大小：全局批大小为 $`B`$，集群设备数为 $`W`$。输入批次沿 Batch 维度均分为 $`W`$ 份，单卡实际处理局部样本矩阵形状为 $`[B/W, D]`$。各卡基于本地样本独立执行前向计算并产出局部损失。

* **梯度全局规约与更新一致性（Gradient All-Reduce Synchronization）**

    * > **机理**：各节点独立反向传播计算出的参数梯度各不相同，在优化器更新（`optimizer.step()`）之前，必须调用全局 All-Reduce 对各卡梯度执行求和并除以 $`W`$ 求均值。

    * 模块化解耦与显存缺陷：DDP 将整个前向与反向网络视为黑盒，代码侵入性极低；但显存扩展收益为零，每张卡均全量冗余维护模型参数、反向梯度及优化器状态。

    * 运行约束：要求全局批大小满足 $`B \ge W`$，且最好为 $`W`$ 的整数倍。

### 静态显存精细核算

* **单参数混合精度显存分解（Per-Parameter Memory Footprint）**

    * > **定义**：在 16 位混合精度（FP16/BF16）搭配 Adam 优化器训练时，维持单个模型参数更新所需的静态显存开销核算模型。

    * 单参数显存分解（设模型参数量为 $`\Phi`$）：
        * 模型参数（FP16/BF16）：占用 2 字节（$`2\Phi`$）。
        * 反向梯度（FP16/BF16）：占用 2 字节（$`2\Phi`$）。
        * FP32 主权重副本（Master Weights）：占用 4 字节（$`4\Phi`$），维持高精度累加更新。
        * Adam 一阶动量矩（Momentum, $`m_t`$）：占用 4 字节（$`4\Phi`$），FP32 跟踪历史梯度均值。
        * Adam 二阶方差矩（Variance, $`v_t`$）：占用 4 字节（$`4\Phi`$），FP32 跟踪梯度平方均值。
        * 此配置静态显存总计为 16 字节/参数；不维护独立主权重、使用不同梯度/状态精度或分片、卸载时，应重新核算，16 不是所有 AMP 训练的固定常数。

* **静态显存占比结构分析（Static Memory Breakdown）**

    * > **机理**：在上述配置中，Adam 的两个 FP32 矩占 8 字节/参数；把 4 字节主权重归入优化器管理的状态后合计 12 字节。两种统计口径应区分。

    * 显存膨胀倍率：一个权重仅占 20 GB 显存的 10B 参数模型，进入混合精度 Adam 训练流程后，仅静态状态即霸占 160 GB 显存。在朴素 DDP 下，该 16 字节/参数的状态在集群所有 GPU 上全量克隆复制。

    * > **显存核算**：静态状态和激活都可能成为主要瓶颈，取决于模型、序列长度、微批大小、并行度与重计算。应测量峰值，不能预先断言激活不是主要来源。

### 零冗余优化器分片机制

* **优化器状态分片（ZeRO Stage 1）**

    * > **定义**：保留各卡全量参数与梯度，仅将 Adam 优化器状态（FP32 主权重、动量矩、方差矩）均分至各卡分别维护的显存优化技术。

    * 执行时序与通信等价性：
        1. 各卡在本地微批次上完成前向与反向传播，产出全量本地梯度。
        2. 反向传播后 Reduce-Scatter 梯度；若梯度总字节数为 $`S_g`$，Ring 单卡发送量为 $`(W-1)S_g/W`$。
        3. 各卡利用本地分片的优化器状态更新管辖的参数分片。
        4. All-Gather 更新后的参数；若参数总字节数为 $`S_p`$，Ring 单卡发送量为 $`(W-1)S_p/W`$。

    * 通信代价：上述 ZeRO-1 单卡发送量为 $`(W-1)(S_g+S_p)/W`$；DDP Ring All-Reduce 为 $`2(W-1)S_g/W`$。仅当参数与梯度字节数相同等条件成立时，两者发送量相等；参数个数 $`\Phi`$ 不能直接当字节数。

* **梯度分片与计算图反向流水（ZeRO Stage 2）**

    * > **定义**：在优化器状态分片基础上，进一步消除单卡全量梯度常驻显存的技术。

    * 逐层释放机理：ZeRO-2 在梯度规约后保留负责的梯度分片，可释放其他部分；缓冲与峰值受 bucket 和实现影响。其集合通信量应按梯度、参数各自的字节数核算。

### 全分片数据并行与双流异步重叠

* **全分片执行生命周期（ZeRO Stage 3 / FSDP）**

    * > **定义**：将模型参数、梯度与优化器状态全部均匀分片至各节点，单卡静态仅持有各状态的 $`1/N_{\text{GPU}}`$，在前向与反向传播中按需动态拉取并即时销毁的全分片并行范式。

    * 单层执行生命周期：
        * 前向传播阶段：执行某层前向计算前，调用 All-Gather 动态从全网收集该层完整参数，完成本地前向计算后立即销毁非本地参数显存。
        * 反向传播阶段：计算图逆向回溯至该层时，再次调用 All-Gather 重新收集该层完整参数，结合激活值算得该层梯度后立即调用 Reduce-Scatter 派发梯度切片，随后再次销毁该层完整参数与非本地梯度。

    * 通信量定量核算：若前向后重新分片、反向再次收集参数，Ring 发送量约为 $`(W-1)(2S_p+S_g)/W`$；同精度时约为 DDP 的 1.5 倍。若保留完整参数到反向、使用不同精度或其他策略，次数和比例会改变。

* **CUDA 双流异步重叠机制（Compute-Communication Overlap）**

    * > **定义**：利用 GPU 硬件内部多条独立队列，将计算流的张量核心运算与通信流的网络数据搬运重叠并行的系统实现。

    * 时序掩盖机理：当前层计算可与下一层参数预取重叠；每层计算必须等待该层 All-Gather 的完成事件。下面展示有足够计算窗口时的前向示意。

      ```mermaid

        gantt:
          displayMode: compact

          dateFormat x
          axisFormat %S
          tickInterval 1second
          todayMarker off
      ```

    * 显存与扩展收益：FSDP 降低每卡静态状态，但还需要完整活跃层、激活和通信缓冲。8×80 GB 共 640 GB，按 16 字节/参数，50B 仅静态就需 800 GB，无法仅靠分片装下；12 字节/参数也需 600 GB，余量很小，是否能训练还依赖卸载、精度与峰值测量。

### 临界批大小约束与扩展边界

* **临界批大小算法瓶颈（Critical Batch Size Constraint）**

    * > **定义**：优化算法理论中限制训练样本批次无限制扩张的数学阈值。

    * 边际收益递减：超过临界批大小后，增加 batch 对减少所需更新步数的收益趋于饱和，并不意味着梯度方差严格为零。该阈值依赖目标损失、训练阶段和优化器。

    * > **易错点**：大 batch 的硬件吞吐收益应与样本效率一起评估；越过临界批大小不自动导致过拟合或收敛停止，应结合学习率、训练预算与实测曲线判断。

* **算力扩展边界转移（Transition to Model Parallelism）**

    * > **规则**：数据并行（包括 DDP 与 FSDP）横向扩展的前提是拥有足够大的全局批大小支撑。一旦全局批次触碰临界批大小上限，或单步前向激活值膨胀击穿单卡显存，单纯数据并行宣告耗尽扩展空间，系统必须转向模型并行（张量并行、流水线并行）。

## 张量并行与序列并行

### 矩阵投影切分与前反向算子对偶

* **列张量并行与行张量并行（Column and Row Parallel GEMM）**

    * > **定义**：将全连接线性层的权重矩阵沿着列维度或行维度切分、由多设备协同完成通用矩阵乘法（GEMM）的算子级切分范式。

    * 切分与计算机理：
        * 列张量并行：输入矩阵 $`X \in \mathbb{R}^{B \times D}`$ 复制保留在所有设备上，权重矩阵 $`W \in \mathbb{R}^{D \times D}`$ 沿列特征维度均分为 $`T`$ 份（$`[W_1, W_2, \dots, W_T]`$）。各卡本地独立计算 $`Y_i = X W_i \in \mathbb{R}^{B \times \frac{D}{T}}`$。各卡显存承载参数量缩减为原先的 $`1/T`$。
        * 行张量并行：权重矩阵沿行维度均分为 $`T`$ 份（$`W = \begin{bmatrix} W_1 \\ \dots \\ W_T \end{bmatrix}`$）。各卡使用输入的局部特征切片与对应行切片相乘，产出尺寸完全相同的局部矩阵，末尾通过一次 All-Reduce 将各卡局部结果累加还原为全局输出。

* **Transformer 核心模块张量并行编排（Transformer Block Tensor Parallelism）**

    * > **机理**：为避免在非线性激活函数处引入跨卡通信，将列并行与行并行按顺序配对编排。

    * 多层感知机（MLP）切分编排：
        * 升维全连接层采用列并行切分（$`A = [A_1, A_2]`$），各卡本地计算 $`X A_i`$。由于 GeLU/ReLU 激活函数严格按元素（Element-wise）独立执行，各卡直接在本地计算 $`\text{GeLU}(X A_i)`$，全过程零卡间通信。
        * 降维全连接层采用行并行切分（$`B = \begin{bmatrix} B_1 \\ B_2 \end{bmatrix}`$），各卡使用本地激活计算 $`\text{GeLU}(X A_i) B_i`$。
        * 模块末端调用单次 All-Reduce 将各卡局部乘积累加，恢复全局输出 $`Z`$。

    * 自注意力机制（Self-Attention）切分编排：$`W_Q, W_K, W_V`$ 投影矩阵按注意力头数执行列并行切分，多头注意力在各卡本地独立并行计算；输出投影矩阵 $`W_O`$ 执行行并行切分，末端调用单次 All-Reduce 完成聚合。

* **轻量级组件全量复制规则（Replication of Lightweight Ops）**

    * > **规则**：普通 TP 常复制轻量算子；结合 SP 后，LayerNorm、Dropout 等可沿序列分片执行。是否复制应按张量布局和通信代价决定。

* **前向反向算子数学对偶性（Forward-Backward Operator Duality）**

    * > **定义**：张量并行计算图中，前向传播与反向传播在集合通信原语上呈现的镜像对称与对偶互换关系。

    * 对偶映射规律：
        * 算子对偶：将列并行的输入端算子抽象为 $`f`$，行并行的输出汇聚端算子抽象为 $`g`$。在前向传播中，$`f`$ 为恒等复制（Identity），$`g`$ 为全规约（All-Reduce）；在反向传播梯度回传中，两者镜像对调：$`g`$ 变为恒等复制（下游梯度天然完整），$`f`$ 转变为全规约（All-Reduce，累加各卡局部输入梯度以生成前级偏导数）。
        * 通信原语对偶：前向传播中张量由分片通过 All-Gather 汇聚为完整状态之处，在反向传播中上游完整梯度必通过 Reduce-Scatter 在对应维度规约并重新分散切片。

### 通信频次与节点拓扑约束

* **高频全规约通信负载（High-Frequency Collective Overhead）**

    * > **机理**：在每个 Transformer 块中，MLP 模块与 Self-Attention 模块的前向计算各自需要一次 All-Reduce，反向梯度计算同样各自需要一次 All-Reduce，单层单步累计触发 4 次 All-Reduce 通信。

    * 传输数据量：一个 $`[b,s,h]`$ 激活张量占 $`q b s h`$ 字节，$`q`$ 为元素字节数。单次 Ring All-Reduce 的发送量约为 $`2(T-1)q b s h/T`$；应再按前后向调用次数累加，不能把整块通信量当单次消息。

* **单机 NVLink 域拓扑绑定铁律（Intra-Node NVLink Confinement）**

    * > **边界规则**：TP 适合高带宽、低延迟互联域，传统 8 卡服务器通常把 TP 放在节点内。NVL72 等互联域可跨计算托盘；跨节点 TP 也可以使用，是否划算由实测决定，没有 TP≤8 的普遍硬上限。

### 逐点运算显存孤岛与序列并行

* **逐点算子显存孤岛（Pointwise Activation Bottleneck）**

    * > **机理**：张量并行将 MLP 与 Attention 的权重及矩阵乘法激活除以了加速器数量 $`T`$，但 LayerNorm、Dropout 与残差连接等逐点算子在各卡全量复制执行，导致单层仍有固定的约 $`10 s b h`$ 激活显存无法被 TP 分摊，形成显存缩减阻碍。

* **序列并行序列轴分片机理（Sequence Parallelism Mechanics）**

    * > **定义**：作为张量并行在逐点运算上的天然附属扩展，将输入激活沿序列长度轴（$`s`$ 轴）均匀分片至各加速器的并行技术。

    * 协同执行流程：
        1. 在 LayerNorm、Dropout 与残差连接区域，张量按序列轴切分（尺寸为 $`[s/T, b, h]`$），各卡独立执行逐点运算。
        2. 在进入 GEMM 矩阵乘法前，调用 All-Gather 在序列维度拼齐完整序列激活（$`[s, b, h]`$）。
        3. 执行列并行与行并行 GEMM。
        4. 行并行输出端不再执行 All-Reduce，而是直接执行 Reduce-Scatter，在累加部分和的同时沿序列轴重新分散为切片格式（$`[s/T, b, h]`$）。

    * > **区别**：Megatron 式 SP 分片逐 token 的算子，并在 TP 组内交换序列布局；CP 分片注意力上下文，需交换 KV 或注意力部分结果。CP 可用 Ring、All-Gather、All-to-All 或分层实现，并非只支持 Ring，也不等同于位置编码的长度外推。

* **前向反向通信对偶映射（SP Communication Duality）**

    * > **规律**：序列并行在前向传播中先执行 All-Gather、后执行 Reduce-Scatter；在反向传播中，两者的执行位置与顺序严格对调，反向计算图先执行 All-Gather 拉取序列梯度、计算后执行 Reduce-Scatter 分散梯度切片。

### 激活显存建模与激活重计算

* **激活显存参数化模型（Activation Memory Analytical Model）**

    * > **公式**：在未采用并行切分与激活重计算的基线环境下，单层 Transformer 激活显存占用公式为：

        $`\displaystyle \text{Activation Memory} \approx s b h\left(34 + \frac{5as}{h}\right)=34sbh+5abs^2\quad\text{字节}`$

        其中 $`s`$ 为序列长度，$`b`$ 为批大小，$`h`$ 为隐藏层维度，$`a`$ 为注意力头数。

    * 分量机理：该论文按特定 Transformer、精度与保存策略推导：线性项为 $`34sbh`$，注意力中间矩阵项为 $`5abs^2`$。FlashAttention 避免在 HBM 保存完整注意力矩阵，但仍保存输入、输出和归一化统计，实际系数需按实现重新核算。

* **结合 SP 的理论极限压缩下限（Theoretical Lower Bound with SP）**

    * > **结论**：在论文的保存策略下，TP+SP 可把主要线性项降到约 $`34sbh/T`$；这是该模型下的估计，不是所有实现的理论下限。

        $`\displaystyle \text{Activation Memory Lower Bound} \approx \frac{34 s b h}{T}`$

        激活主体可近似按 $`1/T`$ 缩减，但未分片张量、缓冲和固定开销会限制实际收益。

* **激活重计算细粒度权衡（Selective Activation Recomputation）**

    * > **定义**：在前向传播中丢弃部分中间激活值、在反向传播需要时重新在前向算子中就地计算以节省显存的技术。

    * 模块重计算策略权衡：
        * Attention 核心：当序列相对隐藏维度较短时，重算注意力中间结果可用较小计算开销省下较多保存空间；长序列下 $`O(s^2h)`$ 运算仍可能昂贵。
        * MLP 块：重算矩阵乘法会增加计算，但 MLP 激活也可能占主要显存；全层或选择性 MLP 重计算在工程中同样常见，应根据峰值与吞吐选择。

    * 系统工程置换哲学：以约 20%~30% 的额外前向算力开销置换宝贵 HBM 显存，腾出的显存空间可容纳更大的单步批大小，进而使硬件 Tensor Core 处于满负荷运算区间并稀释流水线气泡，推高全集群总体算力利用率。

## 流水线并行与气泡抑制

### 层级切分与点对点通信

* **深度层级切分机理（Depth-wise Partitioning）**

    * > **定义**：沿着神经网络的层深维度（Depth Dimension）将连续网络层横向切块并分配至不同流水线阶段（Stages/GPUs）的并行范式。

    * 阶段切分示例：在 4 级流水线配置下，Rank 0 维护第 $`0 \sim 7`$ 层，Rank 1 维护第 $`8 \sim 15`$ 层，依此类推。前向计算逐级向后推送，末级 Rank 计算损失后启动反向传播逆向回传。

* **点对点通信与物理拓扑适配（P2P Communication and Placement）**

    * > **机理**：流水线并行设备间完全局限于相邻阶段之间的点对点通信（P2P，`dist.send` 与 `dist.recv`），传输数据仅为层间边界激活值或反向偏导数，单次通信量为：

        $`\displaystyle \text{单次消息字节数}=q\,bsh`$

        其中 $`b`$ 为微批大小，$`s`$ 为序列长度，$`h`$ 为隐藏层维度。

    * 拓扑编排：PP 常用于连接相对较慢的互联域，但链路延迟、激活尺寸、阶段平衡与调度仍影响吞吐，不能保证适合任意广域链路。

### 微批次划分与气泡调度模型

* **流水线气泡（Pipeline Bubbles）**

    * > **定义**：由于前后层级串行数据依赖导致各加速器在流水线充盈与排空期间处于算力休眠的空闲时间段。在单体大批次朴素调度下，同一瞬间全集群仅有一张卡在运转，硬件利用率趋近于崩塌。

* **微批次交错填充（Micro-batching Pipelining）**

    * > **机理**：将单步全局批次在输入端细分切碎为 $`m`$ 个独立的微批次（Micro-batches），使后续微批次紧随前序微批次连续灌入管线，压窄首尾等待空转比例。

* **1F1B 稳态调度与气泡比率（1F1B Scheduling and Bubble Ratio）**

    * > **定义**：流水线充盈达到稳态后，各设备交替执行一次前向（Forward）与一次反向（Backward）；两者对应的微批次编号差随阶段和调度位置变化。

      ```mermaid
      ---
      config:
        gantt:
          displayMode: compact
      ---
      gantt
          title 1F1B：4 个阶段、4 个微批次
          dateFormat x
          axisFormat %S
          tickInterval 1second
          todayMarker off
          section Rank 0
          F0 :r0f0, 0, 1s
          F1 :r0f1, 1000, 1s
          F2 :r0f2, 2000, 1s
          F3 :r0f3, 3000, 1s
          空闲 :done, idle0_0, 4000, 3s
          B0 :crit, r0b0, 7000, 1s
          空闲 :done, idle0_1, 8000, 1s
          B1 :crit, r0b1, 9000, 1s
          空闲 :done, idle0_2, 10000, 1s
          B2 :crit, r0b2, 11000, 1s
          空闲 :done, idle0_3, 12000, 1s
          B3 :crit, r0b3, 13000, 1s
          section Rank 1
          空闲 :done, idle1_0, 0, 1s
          F0 :r1f0, 1000, 1s
          F1 :r1f1, 2000, 1s
          F2 :r1f2, 3000, 1s
          空闲 :done, idle1_1, 4000, 2s
          B0 :crit, r1b0, 6000, 1s
          F3 :r1f3, 7000, 1s
          B1 :crit, r1b1, 8000, 1s
          空闲 :done, idle1_2, 9000, 1s
          B2 :crit, r1b2, 10000, 1s
          空闲 :done, idle1_3, 11000, 1s
          B3 :crit, r1b3, 12000, 1s
          空闲 :done, idle1_4, 13000, 1s
          section Rank 2
          空闲 :done, idle2_0, 0, 2s
          F0 :r2f0, 2000, 1s
          F1 :r2f1, 3000, 1s
          空闲 :done, idle2_1, 4000, 1s
          B0 :crit, r2b0, 5000, 1s
          F2 :r2f2, 6000, 1s
          B1 :crit, r2b1, 7000, 1s
          F3 :r2f3, 8000, 1s
          B2 :crit, r2b2, 9000, 1s
          空闲 :done, idle2_2, 10000, 1s
          B3 :crit, r2b3, 11000, 1s
          空闲 :done, idle2_3, 12000, 2s
          section Rank 3
          空闲 :done, idle3_0, 0, 3s
          F0 :r3f0, 3000, 1s
          B0 :crit, r3b0, 4000, 1s
          F1 :r3f1, 5000, 1s
          B1 :crit, r3b1, 6000, 1s
          F2 :r3f2, 7000, 1s
          B2 :crit, r3b2, 8000, 1s
          F3 :r3f3, 9000, 1s
          B3 :crit, r3b3, 10000, 1s
          空闲 :done, idle3_1, 11000, 3s
      ```

      横轴为相对时间槽；本教学例假设各阶段前向、反向各占一槽，忽略通信与参数更新耗时。`Fj`、`Bj` 分别表示微批次 j 的前向、反向，空闲区域为气泡。

      每个 `Fj` 必须等待上游 Rank 的同一微批次前向完成；每个 `Bj` 必须等待本 Rank 的 `Fj` 和下游 Rank 的 `Bj` 完成，末级反向直接依赖本地前向与损失。

      各 Rank 先充盈前向，再交替前向与反向，最后排空反向；例如 Rank 1 的稳态为 F2、B0、F3、B1。

    * 气泡比率定量公式：设流水线阶段数为 $`p`$，微批次数量为 $`m`$：

        $`\displaystyle \text{空闲/有效工作}\approx\frac{p-1}{m},\qquad F_{\text{bubble}}\approx\frac{p-1}{m+p-1}`$

    * 资源约束：使气泡比率趋近于 0 要求微批次数量 $`m \gg p`$。微批次数量的放大本质上依赖于足够大的全局批大小支撑；若全局批大小不足，流水线级数越高则气泡占比越大，导致算力严重浪费。

### 异步通信重叠与零气泡解耦

* **非阻塞异步通信重叠（Non-blocking P2P Overlap）**

    * > **机理**：`isend/irecv` 可与独立计算重叠；需满足流依赖、网络带宽和可用计算窗口，隐藏程度应测量。

* **零气泡流水线算子解耦（Zero-Bubble Pipeline Schedule）**

    * > **定义**：将反向传播计算图内部结构解耦为两个独立算子、利用无外部依赖的计算任务填补流水线气泡缝隙的调度架构。

    * 算子解耦拆分：
        * 激活偏导数计算（$`B`$, Backward for Activations）：计算损失关于本层输入的偏导数 $`\frac{\partial L}{\partial X}`$ 并沿计算图逆向传递给前序阶段，处于流水线推进的关键路径上。
        * 权重梯度计算（$`W`$, Backward for Weights）：计算损失关于本层模型权重的梯度 $`\frac{\partial L}{\partial W}`$，属于计算图局部叶子节点，无外部时序依赖。

    * 填隙调度：权重梯度仍依赖本层激活和输出梯度，但不位于上游激活梯度的关键路径，可延迟到空闲窗口。零气泡调度还依赖阶段平衡、显存与优化器同步等条件。

## 专家并行与非对称混合编排

### 专家并行与稀疏路由机制

* **混合专家模型架构（Mixture of Experts, MoE）**

    * > **定义**：保持自注意力机制为密集计算、仅将前馈网络（MLP/FFN）替换为一组并列专家网络并由门控路由器（Router）将各 Token 动态分配给 Top-$`k`$ 个专家的稀疏模型架构。

* **专家并行切分范式（Expert Parallelism, EP）**

    * > **定义**：将全网独立专家网络切分并均匀分发至集群中不同计算设备的模型并行策略。

* **专家并行与张量并行选型基准（EP vs TP Decision Rule）**

    * > **选型建议**：专家矩阵过小时，额外 TP 可能损害 GEMM 吞吐，EP 往往有利；但还要评估专家容量、负载均衡与 All-to-All 成本，不存在一律优先 EP 的铁律。

    * 底层物理机理依据：
        * 矩阵尺寸与张量核心利用率：张量并行硬性切分矩阵维度，若在原本较小的专家矩阵内部再切分，GEMM 尺寸将暴跌出张量核心最优吞吐区间，单卡算力利用率雪崩；专家并行完整保留单专家的矩阵运算规模。
        * 激活分发通信稀疏性：MoE 层中 Token 路由高度稀疏，专家并行仅需通过网络将少量激活定向分发给对应专家，通信负载轻量；若采用张量并行，必须对整层高维密集激活执行高频全规约，通信开销极其沉重。

### 底层路由通信算子与延迟压榨

* **全对全通信延迟瓶颈（All-to-All Latency Challenge）**

    * > **机理**：专家并行高频执行全局全对全分发与组合（All-to-All Dispatch & Combine），各卡 Token 必须跨网络路由至目标专家，后序计算必须等待全员 Token 到位，对跨机网络延迟与通信抖动极端敏感。

* **汇编级底层算子加速库（Assembly-level Communication Optimization）**

    * > **实现**：为压榨 All-to-All 路由通信能效，前沿系统工程深入微码层级协同优化：
        * DeepSeek DeepEP 库：为 MoE dispatch/combine 提供高吞吐、低延迟 GPU 通信内核，利用 NVLink 和 RDMA 网络；PTX 是虚拟指令集，不能无依据称为“未公开机器指令”。实现细节依版本而变。
        * NVIDIA HybridEP 库：借助硬件自适应路由与多级流水线重叠隐藏跨节点调度延迟。

### 结构非对称性与并行度解耦

* **注意力层与专家层并行偏好冲突（Structural Asymmetry Conflict）**

    * > **机理**：Transformer 内部 Attention 层为密集计算，偏好高张量并行（高 TP）分摊算力与显存；MoE/FFN 层为稀疏计算，偏好极低张量并行（如 $`\text{TP}=1`$ 维持大 GEMM 吞吐）而需要高专家并行（高 EP）。若全局强行绑定相同并行度，将导致 Attention 显存超标或专家矩阵被切得粉碎。

* **跨层并行度解耦与动态重排（Parallelism Decoupling and Resharding）**

    * > **方案**：在同一网络内部彻底剥离 Attention 层的 TP 拓扑与 MoE 层的 EP 拓扑；在两层交界处通过高效跨层张量重排（All-to-All / Resharding）动态重构张量布局，实现非对称混合并行。

### 上下文并行机制

* **上下文并行定义与环形注意力（Context Parallelism / Ring Attention）**

    * > **定义**：将超长输入序列的 Key/Value 激活张量切分到不同加速器组成的逻辑环路上，在自注意力计算的同时沿环形网络异步传递 KV 分块的并行范式。

* **序列外推与显存平摊（Long-Context Memory Distribution）**

    * > **机理**：CP 平摊 KV、激活和注意力计算；Ring Attention 可将分块 KV 交换与计算重叠，但不保证完全隐藏通信，也不会把全局全注意力的总计算量从二次降到线性。

## 多维混合并行设计准则与工业落地

### 屋顶线模型与混合并行决策树

* **计算通信比与屋顶线效率临界线（Roofline Critical Threshold）**

    * > **机理**：分布式训练系统效率取决于计算耗时与通信耗时的相对比率。当单芯片分配到的局部批大小极大时，计算耗时足以完全掩盖通信开销，纯 FSDP 即可处于计算受限区（Compute-bound），GPU 张量核心被充分用满。

    * 多维并行切分意义：随着集群总芯片数激增，受制于临界批大小约束，单卡批次被迫左移缩小；当通信耗时超越计算耗时，纯 FSDP 跌入通信受限区（Communication-bound），算力大量空转。引入 TP、PP、EP 构成 3D/4D 混合并行，能强行将效率曲线向左推移，在极小局部批次下维持计算受限高能效。

* **混合并行编排决策树法则（Parallelism Decision Tree Rules）**

    * 决策执行准则：
        1. 显存足够时优先最大化数据并行（FSDP），获得最纯粹计算吞吐。
        2. 显存不足时执行模型切分：稠密模型在单机 8 卡内启用 TP+SP；MoE 模型优先在高速互联域拉满 EP。
        3. 单机仍装不下时引入流水线并行（PP），跨机架或慢速网络放置 PP 阶段。
        4. 模型完全放置后，集群剩余算力预算全部分配给数据并行（DP）。
        5. 单卡批大小过小导致流水线气泡扩大时，通过激活重计算与梯度累积以微弱算力代价置换更大批次空间。

### 多维并行层级映射黄金法则

* **物理硬件拓扑映射六项原则（Hardware Mapping Golden Rules）**

    * 原则一：能用数据并行就拉满数据并行，非必要不引入模型并行（数据并行实现最解耦、无流水气泡、算力开销最低）。
    * 原则二：优先将高频 TP 放在最快的互联域；EP 的范围同时取决于专家数与网络，DeepSeek-V3 的 64 卡跨节点 EP 就不是单机 8 卡限制。
    * 原则三：PP 常用于连接互联域；按元素精度、激活量与调度核算通信，验证慢链路是否可被隐藏。
    * 原则四：MoE 优先评估 EP 与低 TP，结合专家矩阵尺寸和路由负载选择。
    * 原则五：超长上下文扩展时挂载上下文并行（CP / Ring Attention）。
    * 原则六：只有把累积步骤组织成更多流水线微批次时，梯度累积才可能降低气泡；有效 batch 不变时要重新安排微批与并行配置。

* **并行维度扩展顺序（Scaling Order）**

    * > **规则**：先满足显存约束，再在目标互联拓扑上比较 DP、TP、PP、EP、CP 的吞吐，不能按固定 8 卡上限机械增加并行度。

### 自动分片编译器与显式原语编排

* **声明式与编译器自动分片流派（Declarative Auto-Sharding）**

    * > **定义**：以 JAX / XLA 生态为代表，开发者仅在代码中对多维张量声明分片布局规范（Sharding Annotations），由底层编译器通过计算图变换算法在后台自动推导并插入最优集合通信算子的范式。

* **命令式显式原语编排流派（Imperative Explicit Orchestration）**

    * > **定义**：以 PyTorch 底层研发为代表，工程师显式调用 `all_reduce`、`all_gather` 及点对点通信原语，精确把控数据流向与显存生命周期的范式。

    * 工程价值对比：声明式编译器降低了开发者心智负担；显式原语编排则赋予底层系统开发不可替代的工程可控性，是精准诊断大规模集群算力雪崩、通信死锁与带宽暴跌等故障的底层基石。
